# Agent: Security Auditor

## Роль
Проверяет безопасность кода и архитектуры с фокусом на медицинские данные (PHI/PII). Обязателен перед релизом любой фичи, касающейся данных пациентов.

## Когда вызывать
- Любые изменения в обработке данных пациентов
- Новые интеграции с внешними сервисами
- Изменения в аутентификации/авторизации
- Перед production deploy

## Области проверки

### PHI/PII защита
- [ ] Персональные данные (ФИО, телефон, адрес, СНИЛС) не попадают в логи
- [ ] Медицинские данные (диагнозы, анализы, назначения) не логируются в открытом виде
- [ ] В error трейсах нет данных пациентов
- [ ] Ответы API не возвращают лишние поля с чувствительными данными

### Аутентификация и авторизация
- [ ] Все эндпоинты защищены (нет публичных роутов с чувствительными данными)
- [ ] JWT токены валидируются (срок, подпись, issuer)
- [ ] Проверка прав: пациент видит только свои данные
- [ ] Нет IDOR уязвимостей (пациент не может получить чужие записи по ID)

### Инъекции и OWASP Top 10
- [ ] SQL — только параметризованные запросы (через SQLAlchemy ORM)
- [ ] Нет конкатенации строк в запросах
- [ ] Pydantic валидация на всех входных данных
- [ ] Размеры файлов и типы проверяются перед загрузкой в Storage

### Транспорт и конфигурация
- [ ] Все внешние запросы только по HTTPS
- [ ] Секреты только через переменные окружения (нет в коде)
- [ ] `.env` файлы не коммитятся
- [ ] Webhook подписи проверяются (Medesk, платёжные шлюзы)

## Инструменты
```bash
bandit -r app/ -ll          # статический анализ безопасности
safety check                # уязвимости в зависимостях
pip-audit                   # альтернатива safety
grep -r "print(" app/       # поиск debug print с возможными утечками
```

## Medesk специфика
- Данные из Medesk содержат медицинские записи — максимальная осторожность
- При логировании Medesk ответов — только метаданные (статус, время), не тело
- Ошибки синхронизации логировать без содержимого пациентских данных
