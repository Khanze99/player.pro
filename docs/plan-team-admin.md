# План: администрирование команд организации

Статус: план, реализация не начата. Дата составления: 2026-09-20.

## Зачем

Сейчас админ создаёт ровно одну команду — во время онбординга организации
(`mobile/src/app/(auth)/org-create.tsx`). Модель данных и права на бэкенде уже
поддерживают много команд на организацию, но в приложении нет пути добавить
вторую команду, переименовать её или закрыть — это и есть пробел, который
нужно закрыть.

## Что уже есть

| Есть | Где | Что это даёт |
|---|---|---|
| `teams.org_id` — 1:N без ограничений | `app/models/team.py:16` | Организация уже может иметь сколько угодно команд, `UniqueConstraint` нет |
| `POST /teams` | `app/api/v1/teams.py:13`, `authz.require_org_admin` | Создание команды — только у org-admin; создатель автоматически становится `head_coach` новой команды |
| `GET /teams` | `app/api/v1/teams.py:19` → `teams_service.list_my_teams` | Для org-admin уже возвращает **все** команды организации, не только «свои» |
| Управление составом | `PUT/DELETE /teams/{id}/members` | Доступно org-admin **или** `head_coach` конкретной команды |
| Клиентский хук | `mobile/src/api/hooks.ts:52` `useMyTeams` | Уже используется в `CoachHome` (переключатель команд) и `invite.tsx` (выбор команды при инвайте) — подхватит новые команды без правок |

## Чего не хватает (пробел end-to-end)

- Нет экрана для создания команды **после** онбординга — `POST /teams` вызывается ровно один раз, из `org-create.tsx`.
- Нет ручки редактирования команды (переименование, вид спорта).
- Нет ручки архивации/удаления команды.

## Бэкенд: что добавить

1. **`PATCH /teams/{id}`** — rename + `sport`. `authz.require_org_admin` + проверка `team.org_id == user.org_id`.
2. **Архивация вместо hard delete.** FK на `team_id` (`team_memberships`, `locations`, `events`, `invitations`) объявлены без `ondelete=CASCADE` → Postgres сам заблокирует `DELETE` при живых связях (NO ACTION/RESTRICT по умолчанию). Поэтому:
   - добавить `Team.archived_at: datetime | None`;
   - `DELETE /teams/{id}` = проставить `archived_at`, не физическое удаление;
   - исключить архивные команды из `list_my_teams` / `GET /teams`;
   - миграция через `make migration m="..."` (не руками).
3. Тесты: authz-правила нового эндпоинта + сервисный слой (обязательное покрытие по CLAUDE.md).

## Фронтенд: что менять

1. **Новый экран** `mobile/src/app/teams-admin.tsx` (по образцу `invite.tsx`) — список команд организации на основе уже существующего `useMyTeams`, с действиями «создать», «переименовать», «архивировать».
2. **Точка входа**: в `profile.tsx`, в админ-блоке (`isAdmin`, рядом со строкой `profile.invite` → `/invite`) добавить пункт меню → `router.push('/teams-admin')`.
3. **Переиспользовать форму создания команды**: сейчас поля name/sport зашиты прямо в `org-create.tsx`; вынести в общий компонент, чтобы использовать и в онбординге, и в новом экране.
4. **Новые мутации** в `api/hooks.ts`: `useCreateTeam`, `useUpdateTeam`, `useArchiveTeam` — инвалидировать `queryKey: ['teams']` по успеху (этот ключ уже используют `CoachHome` и `invite.tsx`, обновятся сами).
5. **Типы**: `TeamOut` на бэке уже отдаёт `sport`, но клиентский тип команды сейчас `{ id, name }` (`hooks.ts:53`) — расширить в `api/types.ts`, иначе поле недоступно в форме редактирования.
6. i18n-строки под новый экран (ru/en/es).
