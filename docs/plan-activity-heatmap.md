# План: карта активности (GitHub-style) за 12 месяцев

Статус: **проектирование, код не начат.** Дата составления: 2026-10-24.

Дополняет `PlayerPro_TZ_final.md`: там есть «стрик» (дни подряд, раздел 4.6/7.3,
уже реализован — `Streak`, `streaks_service`) и упоминание «лёгкой геймификации
(бейджи) — опционально», но сетки-календаря активности нет вовсе. Пересечений с
`docs/plan-*.md` не нашёл — новая самостоятельная фича.

## Решения, принятые в обсуждении 2026-10-24

- **Бэкенда это почти не касается.** Сигналы «был опрос в этот день» / «было RPE
  в этот день» — уже отдаётся существующими `GET /wellness/me` и `GET /rpe/me`
  (у `WellnessEntry`/`RpeEntry` уже есть `date`), просто с окном 365 дней вместо
  текущих 28/30/90. Ни новой таблицы, ни миграции, ни поля в схеме.
  *Отклонено:* брать сигнал из `DailyMetric.readiness`/`daily_performance` —
  `daily_performance` вообще не прокинут в схему ответа, пришлось бы менять
  контракт ради того, что уже есть проще и честнее через сами записи.
- **Два сигнала — не один.** Опрос и RPE — разные действия, красим клетку в
  4 состояния: ничего / только опрос / только RPE / оба. Не схлопываем в один
  бинарный «была активность», иначе пропадает смысл различать опрос и RPE,
  который явно просили.
- **Только мобилка.** У веба нет «домашнего экрана игрока» — это кабинет
  тренера/врача (`CLAUDE.md`), личного режима там не существует.
- **Показываем и в отчёте тренера/врача** (`athlete/[id]/index.tsx`), не только
  на своём «Доме». Данные не чувствительные (факт заполнения, не содержание) —
  в отличие от веса это не спецкатегория, гейта `body_metrics` не нужно, то же
  `ensure_can_view_athlete`, что у остального отчёта. Решение по аналогии: раз
  тренеру уже показываем RPE-историю и опросы целиком, показывать факт их
  регулярности — не новая дыра.
- **Неделя начинается с понедельника** (ru-конвенция, как в `dateLabel`
  домашнего экрана, который тоже на `i18n.language`, но дни недели в сетке —
  с понедельника независимо от локали, как в GitHub по умолчанию для всех).
- **Горизонтальный скролл, авто-проскролленный к сегодня** — 53 колонки (недели)
  не влезают по ширине экрана, тот же приём, что у самого GitHub на мобиле.
- **Тап по клетке — тост с датой и что было** (опрос/RPE/оба/ничего) — такой же
  простой паттерн, что уже есть в проекте (`useToast`), без шторки/модалки.
- **Легенда цвета — вариант A, подтверждён в черновике**
  (`https://claude.ai/code/artifact/b8145645-566c-4ca5-8104-d7c1dff8312c`):
  4 самостоятельных цвета, не разрезанная клетка (вариант B отклонён — мельче
  читается на глаз). Берём существующие токены темы, не новые хексы:
  `none: th.surface2`, `survey: th.brand`, `rpe: th.caution`, `both: th.good`.

## Зачем

Стрик уже показывает «сколько дней подряд», но не даёт картины за год целиком —
где были провалы, насколько регулярно в целом. Игроку — мотивация увидеть свою
историю целиком; тренеру/врачу — быстрый взгляд на дисциплину игрока без
пролистывания истории записей.

## Что уже есть

- `useWellnessHistory(days)`/`useRpeHistory(days)` (мобилка) — уже параметризованы
  окном в днях, используются в т.ч. на этом же экране с другими окнами (1/90).
  `useAthleteWellnessHistory`/`useAthleteRpeHistory` — те же для отчёта штаба.
- `WellnessEntry.date`/`RpeEntry.date` — уже в ответе, больше ничего не нужно.
- Визуальный язык для сеток/спарклайнов — `WeightSparkline.tsx` (react-native-svg,
  `Svg`/`Rect`/`Line`/`Text`, явный themed `fill`, разметка по месяцам с
  `toLocaleDateString(locale, {month:'short'})`) — тот же приём для подписей
  месяцев здесь, не изобретаем второй способ форматирования дат.

## Данные и миграции

Не применимо — ничего не хранится отдельно, никакой новой таблицы.

## API

Не применимо — используются существующие `GET /wellness/me`,
`GET /wellness/athletes/{id}`, `GET /rpe/me`, `GET /rpe/athletes/{id}` с
`date_from`/`date_to` на 365 дней. Контракт не меняется.

## Права доступа

Не применимо — тот же `ensure_can_view_athlete`, что уже гейтит эти два
эндпоинта; новое правило не вводим.

## Аналитика

Не применимо — в `DailyMetric`/Readiness/ACWR не входит, чисто визуализация
уже существующих фактов.

## Мобильный клиент

- Новый компонент `components/ActivityHeatmap.tsx`:
  - Пропы: `wellnessDates: Set<string>`, `rpeDates: Set<string>` (ISO-даты),
    `onCellPress?: (date: string) => void`.
  - Строит сетку 7×~53 от `today - 371д` (округлено до понедельника) до сегодня,
    `Svg`/`Rect` на клетку, цвет по 4 состояниям (токены темы, см. «Решения»).
  - Подписи месяцев сверху (`toLocaleDateString(locale, {month:'short'})`),
    подписи дней недели слева (Пн/Ср/Пт, как в GitHub — не все 7, часть пустых
    для компактности).
  - `ScrollView horizontal`, `contentOffset`/`scrollTo` к правому краю при маунте
    (сегодня всегда видно без скролла).
  - Тап по клетке (если есть `onCellPress`) — `Pressable` вокруг `Rect` или
    обработка через `onPressIn` с вычислением клетки по координате (по образцу
    тапа в `BodyMap`, там тоже `Path.onPress` на SVG-элементе).
- `(tabs)/index.tsx` (`PlayerHome`): новая карточка «Активность за 12 месяцев»
  после карточки «Вес» — `useWellnessHistory(365)`/`useRpeHistory(365)` (новые
  отдельные вызовы, не трогаем существующие окна 1/90 — тот же приём, что уже
  применён для `weightHistory`), тап по клетке → `useToast` с датой и фактами.
- `athlete/[id]/index.tsx` (отчёт тренера/врача): та же карточка, те же окна
  365 дней через `useAthleteWellnessHistory`/`useAthleteRpeHistory`, без
  изменений в правах — тот же `ensure_can_view_athlete`.
- i18n (ru/en/es): `home.activityTitle`, `activity.legend.{none,survey,rpe,both}`,
  `activity.cellSurveyDone`/`cellRpeDone`/`cellBothDone`/`cellNone` (для тоста
  по тапу), общие для обоих экранов (без разделения namespace).

## Персональные и медицинские данные

Не применимо — факт заполнения опроса/RPE не медицинская деталь, уже виден в
истории записей без какого-либо гейта.

## Выкатка

Без фича-флага — чисто аддитивный визуальный компонент над уже отдаваемыми
данными, риск сопоставим с `ReadinessSparkline`/`WeightSparkline`, которые
выкатывались без флага.

## Этапность

Один этап — объём укладывается в один компонент + два места встраивания.

## Декомпозиция

```
1. [mobile]  ActivityHeatmap.tsx (сетка, цвета по черновику, месяцы/дни недели,
             горизонтальный скролл к сегодня, тап → факты)
2. [mobile]  (tabs)/index.tsx: новые фетчи 365д + карточка после «Веса»
3. [mobile]  athlete/[id]/index.tsx: та же карточка, фетчи 365д для чужого игрока
4. [mobile]  i18n ru/en/es
```

`make lint`/`tsc --noEmit` на каждом шаге — тестов backend не требуется, бэкенд
не меняется.

## Риски

- **365-дневный фетч `WellnessEntry`/`RpeEntry`** — тонкие таблицы (1 запись в
  день / несколько в день сессий), за год это сотни строк на одного игрока,
  не тяжелее, чем уже сделанные 90-дневные окна для веса.
- **53 колонки на маленьком экране** — решено горизонтальным скроллом,
  авто-подведённым к сегодня, тот же компромисс, что у самого GitHub на мобиле.

## Открытые вопросы

Нет — объём, оба места встраивания и цвета легенды (вариант A) определены.
