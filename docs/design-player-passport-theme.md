# Промпт: дизайн паспорта игрока — светлая + тёмная тема

Статус: **реализовано в коде** (2026-11-06) — `web/src/components/{Navbar,
ThemeToggle,SeasonStatCard,SeasonStatsSection}.tsx`, `app/layout.tsx`
(blocking theme-init), `app/globals.css` (тёмные токены), `app/api/branding/
logo/route.ts`. `npx tsc --noEmit`, `eslint`, `next build` чистые; не план
фичи (данные/API/authz — `docs/plan-player-season-stats.md`, этот документ
его не дублирует) — визуальное ТЗ, доведённое до кода через артефакт
(`https://claude.ai/code/artifact/33893df2-47b5-4fbf-af19-b431139a3895`).

Повод: в `docs/plan-player-season-stats.md` паспорт игрока визуально
дорабатывался несколько раундов артефактом (`https://claude.ai/code/artifact/
33893df2-47b5-4fbf-af19-b431139a3895`) — выбор клуба/сезона/турнира, лого
организации, радар с чекбоксами показателей, блок сборной. Решили оформить
накопленные решения в один промпт и обсудить тему отдельно, прежде чем катить
паттерн на остальную админку.

## Решения, принятые в обсуждении 2026-11-06

- **Два переключаемых режима, не выбор одного направления.** Светлая
  клиническая тема (текущая, `web/src/app/globals.css`) остаётся дефолтом —
  это осознанное решение CLAUDE.md («рабочий инструмент тренера/врача за
  столом, не приложение игрока»), его никто не отменял. Тёмная тема —
  **новый, явно включаемый режим**, ближе по духу к референсу скаутинг-
  платформы (`Desktop/screen_data.png`, mo360-подобный интерфейс), для тех,
  кто предпочитает плотную тёмную подачу данных. Не авто-переключение по
  `prefers-color-scheme` ОС — выбор темы должен быть осознанным действием
  пользователя (тумблер), не тихой подменой уже задокументированного
  дефолта.
- **Охват сейчас — только паспорт игрока** (`.../athletes/[athleteId]/
  stats`). Остальная админка (команды, состав, отчёт игрока, дашборд)
  светлую тему не меняет, пока паспорт не утверждён. Если после утверждения
  решат катить тему дальше — это отдельный заход, и тогда же обновляется
  формулировка решения в `CLAUDE.md` (сейчас там зафиксирован только
  светлый вариант).
- **Лого — реальный `GET /branding`.logo_url организации**, не
  сгенерированный бейдж с инициалами. Для организаций без загруженного лого
  — грейсфул fallback (см. «Fallback без лого» ниже), не пустое место и не
  ошибка.
- Накопленные по ходу артефакта решения по составу экрана (см. «Состав
  экрана» ниже) фиксируются тут как часть промпта, не переизобретаются в
  каждой следующей итерации заново.

## Состав экрана (зафиксировано артефактом, не меняется этим документом)

- Шапка игрока (имя/амплуа), без изменений.
- ~~Три независимых селекта Клуб / Сезон / Турнир~~ — **сужено до двух,
  2026-11-06**: лого+название организации переехали в шапку админки
  (`Navbar`, общее на весь кабинет, не только паспорт), поэтому отдельный
  селект «Клуб» на самой странице паспорта избыточен и убран. Остаются
  **Сезон** (все записи игрока) и **Турнир** (записи выбранного сезона, по
  умолчанию «Все турниры» — сумма записей сезона, `sumTournaments`). Если
  за сезон несколько команд одной организации (вызов в дубль) — это видно
  прямо в названии опции турнира (`«Кубок Татарстана U17 (Резерв «Б»)»`),
  не отдельным переключателем.
- ~~Карточка клуба: лого + название + турнир (саб-строка) + плашка
  сезона~~ — **убрана, 2026-11-06**: избыточна с селектами Сезон/Турнир
  выше и с лого в шапке. Карточка начинается сразу с тайлов ядра
  (матчи/минуты/голы+per90/передачи+per90/ЖК/КК).
- Строка-фильтр над радаром: **«Показатели N из M»** (чекбокс-панель — что
  идёт на радар, остальное остаётся в текстовом списке серым) + заглушка
  **«Импорт CSV»** (не функциональна, просто место под будущий ввод списком).
  ⚠️ Это выходит за рамки решения `docs/plan-player-season-stats.md`
  («настройка радара — отдельная, более дорогая фича, не нужна прямо
  сейчас», «каталог метрик не редактируется через UI») — если утверждается,
  **план фичи обновляется этим же заходом**, это не тихое расхождение
  документов.
- Радар — крупный, по центру, восемь осей по умолчанию (`on_radar_default`
  каталога — изначально девять, по запросу 2026-11-06 категория
  «Единоборства» сведена к одному показателю на радаре вместо двух), минимум
  3 для отрисовки.
- Список метрик по категориям под радаром.
- ~~Второй блок справа — сборная/представительская команда~~ — **убран
  2026-11-06**. Обсуждали основание, на котором решать, какая запись
  клубная, а какая сборная: `team_label` — свободный текст, поля «это
  сборная» в модели нет. Два варианта на выбор — (а) без нового поля,
  автоматически: «основная» запись — та, где `team_label` совпадает с
  реальной командой игрока, «вторая» — любая ДРУГАЯ запись того же сезона,
  если ровно одна (если их больше — просто пользоваться уже существующим
  селектом «Клуб», блок не показываем); (б) явное поле `team_kind` на
  `season_player_stats`, тренер выбирает тип при вводе. И то, и другое —
  доп. объём ради кейса, который сейчас не является приоритетом. **Решение:
  блок убираем целиком**, несколько клубов за сезон и так видны через
  турнир-опцию с припиской клуба в скобках (см. выше), не отдельным блоком
  рядом. Если понадобится видеть клуб+сборную одновременно — отдельный
  заход, тогда и выбирается основание (а) или (б) выше.

## Fallback без лого

Не у каждой организации есть `organization_branding.logo_url` (сейчас —
только у части: ФK РУБИН, ФК Рубин, KHAMIDOV, Ыыы — остальные без
брендинга). Для них бейдж — инициалы клуба на нейтральном фоне (как в
первой версии артефакта), не пустой квадрат и не плейсхолдер-картинка
«no image».

## Токены: что нужно дорисовать для тёмной темы

Светлая часть не меняется — `web/src/app/globals.css`:`:root`. Для тёмной
нужен параллельный набор под `[data-theme="dark"]` (переключатель — явный
тумблер в Navbar, не `prefers-color-scheme`; состояние — `localStorage`,
per-browser, не на сервере и не в БД, это предпочтение устройства, не
данные пользователя):

| Токен | Светлая (уже есть) | Тёмная (подобрать) |
|---|---|---|
| `--bg` | `#F7F8FA` | тёмная база, ближе к mo360 (не чистый чёрный) |
| `--surface` / `--surface-muted` | белые | два тёмных слоя поверхности, читаемая разница между ними |
| `--border` / `--border-strong` | светло-серые | тёмные, но не сливаются с поверхностью |
| `--text` / `--text-muted` / `--text-faint` | тёмные на светлом | светлые на тёмном, тот же порядок контраста |
| `--accent` / `--accent-hover` / `--accent-soft` | синий `#2D6FE0` | тот же синий или чуть светлее для контраста на тёмном — **не менять смысл акцента**, только яркость/поверхность под него |
| `--good` / `--caution` / `--risk` (светофор) | см. globals.css | пересчитать под тёмную поверхность тем же принципом, что уже описан в комментарии globals.css для светлой (яркие мобильные hex не читались на белом — на тёмной подложке другая переcборка) |

Радар и любые графики — обе темы проходят **`dataviz`-скилл**: цвета
категориальных/sequential шкал через `scripts/validate_palette.js` отдельно
для `--mode light` и `--mode dark` с соответствующей поверхностью, не «тёмная
тема — это светлая с инвертированными цветами на глаз».

   доработан под тёмную тему прицельно был только паспорт. Остальные экраны,
   скорее всего, выглядят в тёмной теме приемлемо «бесплатно» (те же токены),
   но целенаправленно не проверялись и не полировались под неё.
4. **Открыто**: решение, фиксировать ли это как официальный охват (тёмная
   тема — на всю админку, не только паспорт) и обновление формулировки в

## Редизайн 2026-11-06 (второй заход)

- **Шапка игрока**: бейдж с инициалами, имя крупно, чипы амплуа / команда /
  вид спорта (`sportText`, не сырой ключ `football`).
- **Сезон и турнир выпадающими списками** (сезонов за карьеру может быть
  много). При одной записи за сезон селект турнира неактивен, но виден. «Все турниры» = сумма всех записей сезона, включая другие
  команды (`seasonAggregate.ts`), как и медиана команды на бэкенде.
- **Медиана команды** (`GET /season-stats/teams/{id}/benchmark?season=`,
  только штаб команды и admin организации): пунктирный контур на радаре,
  «команда X» под значением оси и в тайлах голов/голевых, риска на полосах
  метрик. В выборку идут игроки с ≥450′ за сезон (`MIN_RELIABLE_MINUTES`),
  ориентир скрыт при выборке меньше 3 игроков: медиана из 1-2 игроков
  раскрывала бы чужие цифры.
- **«Относительно команды»**: топ-3 отклонений выше и ниже медианы по осям
  радара. Формулировка нейтральная, без «сильно/слабо» и без светофора:
  больше не везде лучше.
- **Порог по минутам**: при minutes < 450 плашка «мало игрового времени»,
  полигон игрока на радаре приглушён.
- **Порядок осей и категорий** фиксирован в `seasonStatLabels.orderDefs`:
  удары, пасы, обводки, владение, единоборства. Бэкенд сортирует алфавитом
  ключей, это не футбольная логика.
- Метрики полосками относительно `radar_max`, а не текстом «30 · 2.38/90 · 45%».
- Подписи ядра по виду спорта (`coreText`): «Голы/Голевые/ЖК/КК» только у
  футбола, в форме ввода тоже.
- Убраны: заглушка «Импорт CSV», `window.confirm`/`alert` (удаление
  подтверждается инлайн, ошибка показывается в карточке).
