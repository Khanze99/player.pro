# План: выбор активной команды при входе

Статус: **проектирование, код не начат.** Дата составления: 2026-09-20.

Дополняет ТЗ — раздела про выбор активной команды там нет. Текущее поведение
описано в `docs/functionality.md`: переключение команды — локальный свитчер
прямо на экране (`dashboard.tsx`, `CoachHome.tsx`).

Решения, принятые в обсуждении 2026-09-20:

- **Экран выбора команды показывается один раз за сессию** (сразу после входа),
  а не свитчером на каждом экране — чипы/Segmented убираются из `dashboard.tsx`
  и `CoachHome.tsx`.
- **Сменить команду позже можно без повторного логина** — через пункт в
  профиле, который снова открывает тот же экран выбора. Альтернатива
  «фиксировать на весь сеанс до re-login» отклонена: для тренера, ведущего
  несколько команд ежедневно, это был бы регресс по сравнению с нынешними
  чипами.
- **Гейт касается только staff/admin с более чем одной командой** — то самое
  условие, по которому свитчер показывается сейчас (`teams.length > 1`).
  Игроков (`global_role: player`) фича не затрагивает: у них другой домашний
  экран (`PlayerHome`) и понятие «активной команды» там не используется.
- **Выбор персистится на устройстве** и переживает перезапуск приложения,
  сбрасывается при выходе из аккаунта.

## Зачем

Свитчер команд сейчас продублирован как локальный `useState` в двух местах
(`dashboard.tsx`, `CoachHome.tsx`) и будет копироваться в каждый новый
coach/admin-экран, которому нужен контекст команды. Плюс это лишняя постоянная
панель на экране ради выбора, который обычно не меняется в рамках сессии —
логичнее один раз спросить при входе и дать сменить по явному действию из
профиля, а не держать управление всегда на виду.

## Права доступа

Не применимо на бэке — набор команд уже отфильтрован по роли/членству в
`list_my_teams`. На клиенте условие показа гейта: `isStaff && teams.length > 1`
— то же самое, что сейчас включает свитчер.

## Мобильный клиент

1. **Стор активной команды.** Поле `activeTeamId: string | null` (в
   `auth/session.ts` либо отдельный небольшой zustand-стор — предпочтительно
   отдельный, чтобы не смешивать конкерн авторизации с конкерном «какая команда
   выбрана»), персистится через `AsyncStorage` (не secure-store — данные не
   секретные). Ключ не привязан к `userId`: устройство через PIN держит одного
   активного пользователя одновременно. Экшены: `setActiveTeam(id)`,
   `clearActiveTeam()` — второй вызывается из `session.signOut()`.
2. **Экран выбора** `mobile/src/app/team-choice.tsx`. Вне группы `(auth)`, так
   как открывается и после входа (из профиля), не только при онбординге.
   Список команд из `useMyTeams()`, тап → `setActiveTeam(id)` →
   `router.back()` (открыт из профиля) либо `router.replace('/')` (открыт как
   гейт при входе — различать по параметру роута). Вёрстка — список карточек по
   образцу `org-choice.tsx`, не Segmented-чипы: это отдельный полноэкранный
   шаг, а не переключатель «на лету».
3. **Гейт в `(tabs)/_layout.tsx`.** После проверки `status`: если `isStaff`,
   `teams.data.length > 1` и (`activeTeamId` пуст ИЛИ не входит в текущий
   список команд) → `<Redirect href="/team-choice" />` до рендера табов. Если
   команда ровно одна — проставить её активной автоматически, без показа
   экрана (не заставлять тапать единственный пункт).
4. **Убрать локальные свитчеры** из `dashboard.tsx` и `CoachHome.tsx` — вместо
   `useState<teamId>` брать `activeTeamId` из стора. Хуки (`useSquadStatus`,
   `useTeamSummary`, `useTeamInjuries`) не меняются, меняется только источник
   `teamId`.
5. **Пункт в профиле.** В `profile.tsx`, видимый при `isStaff && teams.length >
   1` (не только `isAdmin` — рядовой coach на двух командах должен мочь
   переключаться так же) — строка вида «Команда: {текущее имя}» →
   `router.push('/team-choice')`.
6. **Изменение состава команд между сессиями.** Если сохранённого
   `activeTeamId` больше нет в списке (например, команду архивировали — см.
   `docs/plan-team-admin.md`) — гейт из п.3 сам перебросит на выбор, ничего
   дополнительно делать не нужно. Если появилась новая команда — ничего не
   форсируем, пользователь продолжает с прежней и переключается вручную.
7. **i18n** — строки экрана и пункта профиля (ru/en/es).

## Этапность

Одним шагом — фича небольшая, естественных промежуточных релизов нет.

## Декомпозиция

1. [mobile] Стор `activeTeamId` + персистентность (AsyncStorage) + сброс в
   `signOut()` → значение переживает перезапуск приложения, обнуляется при
   выходе.
2. [mobile] Экран `team-choice.tsx` по образцу `org-choice.tsx` → список из
   `useMyTeams()`, тап сохраняет выбор и возвращает пользователя.
3. [mobile] Гейт в `(tabs)/_layout.tsx` (редирект + авто-выбор единственной
   команды) → с 2+ командами и без сохранённого выбора юзера кидает на
   `team-choice` раньше табов; с одной командой — не кидает.
4. [mobile] Убрать свитчеры из `dashboard.tsx` и `CoachHome.tsx`, завязать на
   стор → чипы визуально пропадают, данные экранов не ломаются.
5. [mobile] Пункт «Команда» в `profile.tsx` → открывает `team-choice.tsx`,
   после выбора возвращает в профиль с обновлённым названием команды.
6. [mobile] i18n-строки (ru/en/es).
7. [tester] Jest: гейт-редирект для 0/1/2+ команд, сброс стора при signOut,
   поведение при команде, пропавшей из списка.
8. [code-reviewer] ревью изменений целиком.

## Риски

- **Утечка выбора между аккаунтами на одном устройстве.** Стор не привязан к
  `userId` — если PIN сбросили и вошёл другой человек, активная команда
  предыдущего не должна протечь. Закрывается сбросом в `signOut()`; оба места,
  где он сейчас вызывается (неверный PIN до исчерпания попыток, 401 от
  сервера), уже это покрывают — но стоит явно протестировать оба пути.
- **Гонка на старте.** `useMyTeams()` асинхронный — на первом рендере
  `(tabs)/_layout.tsx` данные ещё не пришли. Нужен явный `loading`-стейт гейта
  (не мигать табами до ответа), по аналогии с уже существующей обработкой
  `status === 'loading'`.
