## Шаг 1. Инфраструктура и конфиг

- **Том под гербы.** Прод-compose должен содержать том `branding_data` и маунт
  `/app/static/branding` у сервиса `api` (шаблон в `docs/deploy.md`, шаг 1 — уже
  включает). Если на ВМ крутится свой compose не из шаблона — добавить том и маунт
  вручную, иначе герб исчезнет при первой пересборке образа.
- **nginx.** Герб раздаёт бэкенд по `/static/branding/...`, клиент запрашивает его как
  `EXPO_PUBLIC_API_URL + /static/...`. Catch-all `location /` на `api` это покрывает —
  убедиться, что нет отдельного правила, режущего `/static/`.
- **`backend/.env.prod`:**
  - `FEATURE_NUTRITION_ENABLED` — по умолчанию `false`. Пока флаг не `true`, дневник
    питания и каталог продуктов пользователю не видны. Решить, включаем ли в этот релиз.
  - `TERMS_POLICY_VERSION` / `HEALTH_CONSENT_POLICY_VERSION` — есть дефолты (`2026-09-03`),
    трогать только при смене текста документов (тогда согласие переспрашивается).

## Шаг 2. Последовательность на сервере

```bash
CO="docker compose -f infra/docker-compose.prod.yml"

# 1. Пересобрать api с новым кодом
$CO up -d --build api

# 2. Миграции — 3 штуки, применяются линейно (ветвления нет, merge-миграция не нужна):
#      off_barcode_partial_unique_index → organization_branding → onboarding_policy_consent
$CO exec api alembic upgrade head
$CO exec api alembic current    # должно совпасть с alembic heads: 69f0c8d7ffb8

# 3. СКРИПТ 1 — брендинг ФК «Рубин». Герб сначала кладём внутрь контейнера:
#    том branding_data с хоста напрямую не виден.
$CO cp backend/themes/rubin.json api:/tmp/theme.json
$CO cp crest.png api:/tmp/crest.png
$CO exec api python scripts/seed_branding.py \
    --org "ФК Рубин" --file /tmp/theme.json --logo-file /tmp/crest.png
#    → печатает предупреждения о контрасте нечитаемых пар — просмотреть глазами.
#      Требует, чтобы орг «ФК Рубин» уже была в БД (см. шаг 0).

# 4. СКРИПТ 2 — каталог продуктов. Одно из:
$CO exec api python scripts/import_foods.py                        # встроенный выверенный набор
$CO exec api python scripts/import_foods.py \
    --off /tmp/off.csv.gz --country russia --cyrillic              # из дампа Open Food Facts

# 5. Проверка
curl -s https://<домен>/health          # {"status":"ok"}
```

Порядок скриптов между собой не важен; оба — после миграций.

## Шаг 3. Учесть по поведению

- **Гейт согласий не за фича-флагом.** Сразу после деплоя все пользователи, включая
  вошедших по PIN, при первом же запросе к любому приватному эндпоинту получат `403` и
  будут выведены на экран согласий (`require_consented`, обработка на клиенте — в
  `pin.tsx` и `_layout.tsx`). Первый запуск после релиза = обязательный accept.
  Предупредить поддержку.
- **Тема ФК «Рубин»** применится только у пользователей этой организации после логина;
  у остальных — дефолтная синяя, визуально без изменений.
- **Миграция `off_barcode_partial_unique_index`** упадёт, если в проде уже есть
  импортированные OFF-продукты с дублирующимися штрихкодами. На чистом проде (фича
  питания была выключена) — не проблема.
