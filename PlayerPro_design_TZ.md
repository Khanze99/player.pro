# Дизайн-ТЗ — мобильное приложение «PlayerPro / ИгрокПро»

**Область:** клиент React Native / Expo (iOS + Android).
**Фокус документа:** игроцкие экраны (именно их спортсмен трогает ежедневно — от них зависит трение перехода со старого приложения).
**Главная задача дизайна:** сделать переход спортсменов бесшовным — приложение должно быть понятно без обучения, а ежедневные действия занимать секунды.
**Версия:** 1.0.

---

## 1. Принципы дизайна

1. **Один очевидный шаг на экране.** У спортсмена всегда одно главное действие: утром — «Заполнить опрос», после тренировки — «Оценить нагрузку». Это крупная первичная кнопка/карточка, всё остальное — тише.
2. **Скорость важнее полноты.** Ежедневный опрос — до 60 секунд, ввод крупными тап-зонами, без клавиатуры там, где можно тапнуть.
3. **Большой палец, не курсор.** Основные действия — в нижней трети экрана (зона большого пальца). Минимальная тап-зона 48×48 pt.
4. **Знакомые паттерны.** Нижняя таб-навигация, свайпы, стандартные жесты. Никаких изобретённых элементов управления — спортсмен уже знает, как этим пользоваться.
5. **Статус читается за долю секунды.** Готовность и нагрузка — через цвет и форму (кольцо, чип), а не только цифру. Цвет отвечает за смысл, число — за детали.
6. **Пустое — это приглашение, а не тупик.** Пока данных мало, экран объясняет, что делать, а не показывает пустоту (см. состояния «накопление данных»).

---

## 2. Пользователь и контекст

- **Кто:** спортсмен 14–35 лет, привык к мобильным приложениям, но не хочет разбираться.
- **Где:** раздевалка, дом утром, кромка поля — часто спешка, иногда слабый интернет, иногда мокрые/холодные руки.
- **Когда:** утром (опрос) и через 15–30 мин после тренировки (RPE) — по push-напоминанию.
- **Следствия для дизайна:** высокий контраст, крупный шрифт, работа офлайн с явной индикацией, минимум ввода текста.

---

## 3. Информационная архитектура и навигация

Навигация намеренно плоская — **3 вкладки**:

| Вкладка | Что внутри |
|---|---|
| **Дом** | Готовность на сегодня, главные действия (опрос / RPE), стрик, статус нагрузки. Точка входа во всё. |
| **История** | Тренды готовности и нагрузки, стрики, доступность, прошлые записи. |
| **Профиль** | Данные, язык, напоминания, устройства, выход. |

Опрос и RPE — **не отдельные вкладки**, а действия, запускаемые с «Дома» и из push. Так у спортсмена нет выбора «куда идти» — приложение само подсказывает следующий шаг.

## 4. Дизайн-система

### 4.1. Палитра
Тёмная база (сигналы готовности читаются на ней чётко), один брендовый акцент для действий и навигации, и отдельная светофорная система для статусов — они не пересекаются, чтобы «синее» всегда значило «действие», а «зелёное/жёлтое/красное» — «состояние».

| Токен | HEX | Назначение |
|---|---|---|
| `--bg` | `#0C0F16` | Фон приложения |
| `--surface` | `#141A24` | Карточки |
| `--surface-2` | `#1C2430` | Вложенные блоки, поля |
| `--border` | `#263041` | Разделители, обводки |
| `--text` | `#EAF0F7` | Основной текст |
| `--text-muted` | `#8A99AD` | Вторичный текст |
| `--brand` | `#2D8CFF` | Действия, активная вкладка, фокус |
| `--good` | `#2FD27A` | Норма / высокая готовность |
| `--caution` | `#FFB02E` | Осторожно / перетренированность |
| `--risk` | `#FF5C5C` | Риск / низкая готовность / травма |
| `--low` | `#6B7A8D` | Недогруз / недостаточно данных |

Требование к контрасту: текст на фоне — не ниже WCAG AA (4.5:1 для основного, 3:1 для крупного).

### 4.2. Типографика
- **Дисплейный шрифт — Unbounded** (полная кириллица): только крупные числа готовности и вордмарк. Это «фирменный» акцент, применяется дозированно.
- **Основной шрифт — Inter** (кириллица + латиница + расширенная для español): весь интерфейс, заголовки, текст.
- Числа в таблицах/рядах — Inter с табличными цифрами (`tabular-nums`), чтобы колонки не «прыгали».

Шкала (mobile): число готовности 64 / заголовок экрана 24·700 / подзаголовок 18·600 / текст 15·400 / подпись 13·500 (muted) / микро 11.

### 4.3. Сетка и радиусы
Базовый шаг 8 pt (4/8/12/16/20/24). Поля экрана 20 pt. Радиус карточек 18, элементов управления 12. Тени мягкие и редкие — глубину даёт разница поверхностей, не тени.

### 4.4. Компоненты (ядро)
- **Кольцо готовности** — круговой индикатор, цвет = зона, в центре число 0–100 и подпись. Фирменный элемент (см. 4.5).
- **Карточка-действие** — крупная, с иконкой, заголовком, подсказкой и стрелкой. Первичная (brand) и вторичная (surface).
- **Шкала-сегменты 1–5** — ряд из пяти тап-зон с иконкой/эмодзи и подписью крайних значений. Для опроса самочувствия.
- **Шкала RPE 1–10** — крупная, с градиентом от зелёного к красному и текстовыми якорями («легко» … «максимум»).
- **Чип статуса** — компактный индикатор (стрик, зона нагрузки, доступность) с точкой-цветом.
- **Тост** — короткое подтверждение действия («Опрос сохранён»), 2 сек, снизу.

### 4.5. Фирменный элемент — «Пульс готовности»
Кольцо готовности на «Доме» с лёгкой пульсацией (как удар сердца) — отсылка к сути продукта (готовность/пульс) и эмоциональный центр экрана. Пульсация тонкая, уважает `prefers-reduced-motion` (при включённой экономии движения — статичное кольцо). Вся остальная анимация сдержанная.

### 4.6. Состояния (обязательны для каждого экрана)
- **Загрузка** — скелетоны, не спиннер по центру.
- **Пусто / мало данных** — объяснение и действие («Пока считаем твою норму — заполняй опрос каждый день, через пару недель появятся тренды»).
- **Ошибка** — что случилось и что сделать, в голосе интерфейса, без извинений («Нет сети. Опрос сохранён на устройстве и отправится сам»).
- **Офлайн** — явный маркер, что данные сохранены локально и синхронизируются.
- **Успех** — короткий тост + обновление состояния (стрик +1, действие исчезает из списка «на сегодня»).

## 5. Экраны (игрок)

### 5.1. Вход по PIN
- 4 точки + цифровая клавиатура крупными кнопками.
- Ниже — «Войти по коду из SMS/почты» (для нового устройства или если забыл PIN).
- После 4 цифр — мгновенный вход, без кнопки «Подтвердить».
- Ошибка PIN: тряска точек + подсказка о попытках и переходе на код.

### 5.2. Дом (сегодня)
- Приветствие по имени + дата.
- **Кольцо готовности** (зона-цвет, число, подпись «Готовность»). Под ним — статус нагрузки чипом (зона ACWR) и стрик.
- **Главные действия на сегодня** карточками: «Заполнить опрос» (утро), «Оценить нагрузку» после события. Выполненные — сворачиваются в галочку.
- Если опрос ещё не заполнен — карточка опроса первичная (brand) и вверху.
- Внизу — таб-бар.

### 5.3. Ежедневный опрос
- Заголовок + индикатор прогресса (например, «3 из 6»).
- Ряды-шкалы 1–5: сон, энергия, мышечная боль, стресс, настроение — крупные тап-сегменты с эмодзи и подписью крайних. Одно касание = ответ.
- Опционально: часы сна (быстрый выбор), пульс покоя (числовой, необязателен).
- Тумблеры «Травма» / «Недомогание» → при включении раскрывается уточнение (локация/тяжесть/комментарий).
- Кнопка «Сохранить» закреплена внизу. После — тост, стрик +1, возврат на «Дом».
- Цель — 60 сек: без обязательного текста, крупные цели, дефолт на «нормальных» значениях допустим, но не проставляется автоматически (чтобы данные были честными).

### 5.4. RPE после события
- Название и время события (из расписания).
- **Шкала усилия 1–10** (CR10): крупная, градиент зелёный→красный, якоря «очень легко» … «максимальное усилие».
- **Самооценка выступления 1–5**.
- Фактическая длительность (подтягивается, редактируется быстрым степпером).
- Живой предпросмотр: «Нагрузка сессии: RPE × мин = … AU».
- «Сохранить» → тост, действие уходит с «Дома».

### 5.5. История / прогресс
- Стрик крупно + текущая серия.
- График нагрузки за неделю (столбики daily load) + линия ACWR с зонами.
- Тренд готовности (спарклайн/линия).
- Доступность за 90 дней (кольцо/полоса: full / modified / unavailable).
- Список последних записей (опросы, RPE) с возможностью открыть день.

### 5.6. Профиль
- Имя, команда, позиция.
- Язык (RU / EN / ES), время напоминаний (опрос, RPE).
- Доверенные устройства, выход.
- Настройка PIN.

## 6. Онбординг и перевод спортсменов (критично)

Задача — увести с прежнего приложения без сопротивления. Дизайн-меры:

1. **Вход по приглашению.** Тренер/админ приглашает — спортсмен открывает ссылку, вводит телефон/почту, код из OTP, задаёт PIN. 3 шага, без пароля. Никакой ручной регистрации в организацию.
2. **Мгновенная ценность на первом экране.** Сразу после входа — «Дом» с объяснённым кольцом («Заполни первый опрос, чтобы увидеть готовность»), а не пустой дашборд.
3. **Короткий гид (2–3 подсказки).** Первый запуск: коротко показать кольцо, карточку опроса и стрик. Пропускается одним тапом. Не модальный тур на 10 шагов.
4. **Честные пустые состояния.** Пока нет 28 дней истории — бейдж «Накопление данных» вместо пустых графиков, с понятным сроком появления трендов.
5. **Habit loop с первого дня.** Push-напоминание об опросе + видимый стрик формируют привычку сразу — это главный фактор удержания при переходе.
6. **Ничего не теряется офлайн.** Если сети нет (частый случай на объектах) — заполнение сохраняется и уходит само. Спортсмен видит это явно и доверяет приложению.
7. **Знакомая ментальная модель.** Термины со старого продукта (RPE, готовность, нагрузка) сохраняем — не переименовываем, чтобы не пришлось переучиваться.

---

## 7. Доступность
- Тап-зоны ≥ 48×48 pt, отступы между интерактивными элементами ≥ 8 pt.
- Контраст не ниже WCAG AA; статусы дублируются не только цветом (иконка/подпись/форма) — для дальтонизма.
- Поддержка системного увеличения шрифта (Dynamic Type / font scale) без ломки вёрстки.
- `prefers-reduced-motion` — отключает пульсацию и переходы.
- Видимый фокус для внешних клавиатур/навигации.

---

## 8. Локализация (RU / EN / ES)
- Язык — по пользователю (переопределяет организацию); при первом входе берётся системная локаль устройства.
- Все строки — из каталогов, никаких зашитых текстов. Кириллица — первичный сценарий; шрифты обязаны её покрывать (Inter, Unbounded — да).
- Español длиннее русского и английского на ~20–30% — кнопки и подписи тянутся, не обрезаются; макеты проверяются на самом длинном языке.
- Форматы дат/чисел — по локали. Единицы (bpm, мин, AU) — универсальны.

---

## 9. Микрокопирайт (тон)
- Обращение на «ты», коротко, глаголами: «Заполнить опрос», «Оценить нагрузку», «Сохранить».
- Одно действие — одно слово-название по всему пути: кнопка «Сохранить» → тост «Сохранено».
- Ошибки не извиняются и не расплывчаты: говорят, что случилось и что делать.
- Пустой экран зовёт к действию, а не грустит.

---

## 10. Что дальше
Прилагается кликабельный прототип ключевых игроцких экранов (`PlayerPro_prototype.html`) — вход по PIN, «Дом» с кольцом готовности, ежедневный опрос, RPE, история. Прототип задаёт визуальный язык из разделов 4–5; по нему удобно проверить сценарий «спортсмен заполняет опрос за минуту» ещё до разработки.
